# Lighting model review (2026-10-21, TomKal1 fork)

Developed from the user's cutaway lighting screenshot: review a building or room, clip it, inspect solved lighting, export a picture, or pin a revision. No packages, Revit API changes, or format/protocol version changes.

## Using it

1. Open a model, then Pause → LIGHTS → LIGHTING CALCS → **REVIEW MODEL · ISO / PLAN / FLY**. It works with placed Revit rooms even when no calculation set is available. WW Tools' fresh **View in BimGo** request now opens this workspace directly and selects the requested calculation zone.
2. **ISO** uses an orthographic, equal-axis isometric view. The initial scope is the building footprint at the walker's level. Use previous/next level (the first option is all levels), BUILDING / LEVEL, or select a room from the model or the room list. FIND ROOM filters by number, name or level. RESET ISO restores the standard orientation; ROTATE 90° gives another corner.
3. **PLAN** looks straight down, north up. **RCP** looks straight up, north up, with the floor cut away. **FLY** is perspective flight without collision: existing movement bindings, Space / E up, Ctrl / Q down, Shift faster by default; right mouse drag looks. The help text follows rebound keys.
4. In parallel views, right mouse drag orbits (in plan it pans); Shift + right drag pans; movement keys pan and the wheel zooms. Wheel over the dock scrolls its controls. FIT VIEW reframes the scope. The model is composed to the left of the dock.
5. **CLIP** enables/disables the box. **RESET CUT** restores the scope's open ceiling (or open floor for RCP). **Edit box faces / show handles** enables six draggable handles and six min/max sliders, including the two Z faces that cannot be dragged along the viewing direction in a plan. Slider measurements are relative to the scope's lower corner and follow the app's units. Cuts cap the building solids and clip calculation colours, discs, isolines and labels as well.
6. Switch between Materials, Illuminance and Luminance. Materials shows the model's material colours with calculation points and values, without false-colour surfaces. Review starts with neutral directional shading; **Use scene lighting** enables the model's sun and fixture preview. Toggle points, values and isolux; surfaces can be toggled in the false-colour modes. Selected-room statistics and targets stay attached to the selected room, rather than the walker outside the cutaway. Labels work at overview distances, remain bounded to 160 nonoverlapping labels, and respect visible geometry and cuts.
7. **EXPORT PNG** or F12 saves the current viewport to Pictures\BimGo, with the review scope, selected-room statistics, legend and visible numeric values. The dock and section handles are excluded. Material views retain calculation points, values and the legend when results are loaded. Export size follows the window size.
8. **PIN REVISION**, then click a visible model surface, enter a comment and save it. This uses the existing comment, screenshot and markup workflow, anchored to the picked element where available. The saved viewpoint records the review eye and cut. Comment viewpoints use the existing perspective format; the captured image retains the parallel composition.
9. **RETURN TO WALK** or Escape restores the original walking position and section. Review cuts do not dirty/save the model's visibility state. Revision comments persist through the existing save workflow. Switching to another viewer tool closes the review first.

## Implementation

- `GameSession.LightingReview.cs`: workspace state, camera, storey/room scope, cached/searchable room list, section controls, exports and statistics.
- Small hooks in the session, dock, input-situation, comment and render paths. Existing keys are reused contextually; no defaults changed.
- `ReviewFraming` in Core: eight-corner orthographic fitting and GL-depth projection. `FpsCamera` supports a vertical parallel span; screen rays originate at the unprojected near-plane pixel in parallel views.
- `Overlay3D` keeps handle/line pixel sizes constant under parallel projection. Sun shadow cascade fitting uses parallel frustum extents. Perspective-only AO and screen reflections are disabled for parallel views.
- `CalcOverlay` has a dedicated shader carrying world positions and discarding against the existing seven section planes. Moving the box changes uniforms without rebuilding the calculation VBO. Occlusion history resets after cuts change.

## Follow-up: material appearance with calculation points (2026-10-21)

The launch screenshot identifies the walkthrough's **Material colour** mode. Review was already using the same model materials, but it forced every visible fixture into the lighting pass, including up to 480 additional unshadowed sources. This could overwhelm the cutaway. Its Rendered segment also mapped directly to CalcDisplayMode.Off, suppressing points, values and the legend even when their checkboxes were enabled.

Review now has **Materials**, **Illuminance** and **Luminance** tabs. Materials uses a points-only effective overlay while leaving the underlying Off enum unchanged outside review. Thus points, actual numeric values, optional isolux and the legend stay available over the material model, including exports. Surfaces controls appear only for the false-colour views. Existing Points requests map to Materials; the enum and file/live formats are unchanged. Opening review no longer converts an Off calculation view into Illuminance automatically; explicit existing or WW Tools requested result modes are retained.

Review starts with neutral material shading using the renderer's existing classic directional light. The per-pass parameters retain model colours and disable realistic texture/reflection overrides, sun, artificial sources, bloom and distance fog. No global colour, sun, fixture intensity or calculation data is changed. **Use scene lighting** restores the model's lit preview with the normal walking light budget rather than every-fixture accumulation. Orthographic AO remains disabled because the current effect reconstructs perspective depth; this appearance therefore does not reproduce the walkthrough's contact shadows exactly.

Validation: App builds with **0 errors** into `lighting-review-material-build`; all **531 Core tests pass, none skipped**. `tools/check-review-materials.ps1 -BuildDirectory <output-directory>` loads the actual compiled App without a window or GL context and checks 32 combinations of review state, projection/view and result mode. Its real CPU overlay builder confirms a material preview retains the 36 point-disc vertices while excluding the false-colour patch triangle; other modes retain their expected meshes. ## Follow-up: imperial luminance and separate point units (2026-10-21)

Point illuminance already followed the display preference (fc imperial, lx metric), but the luminance legend and ticks were hard-coded to cd/m². Imperial surface luminance now uses foot-lamberts (fL), with **1 fL = 3.4262591 cd/m²** from [NIST SP 811 Appendix B.9](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b9). Core's DisplayLuminance converts display values only: surface shading, source values and saved formats are unchanged.

The legend puts its quantity and unit first, so a long set name cannot conceal them. In luminance mode it explicitly says **SURFACE LUMINANCE [fL]** or **[cd/m²]**. A separate line identifies **Points / values: illuminance · foot-candles (fc)** or **lux (lx)**. The legend's height now reserves room for that caption in both the HUD and exported PNG. The dock also spells out both quantities/units; room statistics identify illuminance even while luminance surfaces are active. Numeric point labels retain their existing readable density rather than repeating a unit at every point. Cached captions and tick values refresh on unit changes; imperial luminance ticks retain one decimal place.

Validation: App builds with **0 errors** into `lighting-review-units-build`. **533 Core tests pass, none skipped**, including NIST's conversion factor and the physical check that a 50%-reflecting diffuse surface under 10 fc has luminance 5 fL. The compiled-App smoke script passes its 32 overlay cases plus **12 unit/mode cases** across metric → imperial → metric, checking actual cached legend/dock captions and numeric tick conversion. `git diff --check` passes. Native visual verification of the expanded captions and PNG export remains open.
